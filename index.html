Study 2 · MSML605 Computing Systems for ML + MSML604 Optimization · Spring 2026

Does speculative decoding speed up a 7B model on one GPU?

The idea is that a small draft model guesses a few tokens and the big model checks them all in one pass. I benchmarked Qwen 2.5 7B with a 0.5B draft on an A100 for draft lengths k = 1 to 10 (400 runs). It was slower at every k.

Why it lost

At batch size 1 both models are memory-bound, so the 0.5B draft ran only 1.22× faster per token than the 7B target. Speculation needs roughly 4× to pay off. I used the PyTorch Profiler and a roofline analysis to find this.

What the textbook model gets wrong

The standard cost model assumes every draft token is accepted independently at the same rate. My data rejected that (p < 0.0001 for drafts of 4+ tokens): acceptance rises with position. A closed-form, position-aware model cut prediction error by 23% on held-out prompt categories. Convex relaxation, UCB1 and Thompson sampling all found the best draft length.

ATLAS: an agent that fact-checks its own answers

It plans a research question, gathers evidence with hybrid retrieval, then checks its own answer one claim at a time and rewrites only what the evidence doesn't support.

Served as a streaming FastAPI app with per-query cost tracing ($0.005 to $0.01 per query on GPT-4o-mini), packaged with Docker, GitHub Actions CI and 97 tests.

Code↗
  1. Plans the question as a task DAG
  2. Runs a ReAct loop over 4 tools
  3. Retrieves with dense + BM25, fused by reciprocal rank fusion
  4. Re-ranks with a cross-encoder
  5. Splits the answer into atomic claims
  6. Checks each claim against its evidence with BART-MNLI
  7. Rewrites only the unsupported claims
